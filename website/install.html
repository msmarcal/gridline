Install

The packages are not yet published to a PPA or the Ubuntu archive. Until then, the install is a source-package build on the target machine: a few minutes, and everything it produces is a plain Debian package that apt can remove again.

Build the packages

$ sudo apt install build-essential debhelper
$ git clone https://github.com/msmarcal/gridline.git
$ cd gridline/packages/gridline
$ dpkg-buildpackage -us -uc -b

Install them

$ sudo apt install ../gridline-*.deb

The build leaves three packages one directory up: gridline-session, gridline-config, and gridline-tools. Installing them through apt resolves their dependencies from the Ubuntu archive automatically: the compositor stack (Hyprland, its portal backend, wayland-utils) from universe, and the desktop shell (the status bar, the notification daemon, the wallpaper tool, the application launcher) alongside it. A terminal is recommended rather than required, so apt installs one by default and removing it later does not remove Gridline; the keybinding asks the system for whichever terminal it uses. The media keys add one more small package.

Gridline assumes a display manager and does not install one: its session entry is a file only a display manager reads, so on a machine without one it does nothing rather than breaking anything. A stock Ubuntu desktop has one.

Be aware of what universe means: Canonical does not commit to security updates for universe packages, so patching the compositor stack is your responsibility, as it is for anything tiling you install by hand today. See the support gap, stated plainly.

Log in to Gridline

Log out. Gridline appears as a session option at the login screen, next to Ubuntu and a bare Hyprland entry. Pick Gridline. Your previous session choice stays one click away.

One thing you will probably meet when you leave it: the compositor tends to crash as the session ends, and Ubuntu's crash reporter may pick it up. That is a known bug in Ubuntu's package, fixed upstream, and not something you did. See known issues for what is and is not understood about it.

If the session refuses to start, that is the capability gate doing its job: the launcher found a promised piece missing, wrote which one to the system journal, and returned you to the login screen rather than start a broken desktop. Read the reason with: 

$ journalctl -t gridline -b

Remove, if you want out

$ sudo apt remove --purge gridline-session

GNOME was never touched. What the packages installed is what removing them takes away.
