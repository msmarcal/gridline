Ubuntu LTS · Wayland · apt only

A tiling session that is just a package away.

Gridline is an optional Wayland tiling desktop for Ubuntu LTS, inspired by Omarchy and Regolith, delivered exclusively as Debian packages. Install it, pick it at the login screen, and your stock GNOME session stays installed, selectable, and supported as the fallback. 

$ sudo apt install gridline-desktop

That one-liner is the target, not the present: the packages are not in a PPA yet, and this site does not pretend otherwise. Today the honest path is building the source package, which takes minutes on Ubuntu 26.04.

waybar on top. hyprland tiles below. all of it from the Ubuntu archive.

Why it exists

You already use Ubuntu and you like using it. You work in the terminal. You saw Omarchy and wanted that. Today your choices are to leave Ubuntu for a rolling base, or to assemble the stack by hand and maintain it yourself forever. Gridline is the third option: the Omarchy-like experience as apt packages on the Ubuntu you already run, with the Ubuntu session sitting intact beside it in case you want out.

It is a personal project with a small audience by design, the way Omarchy's is. That is the nature of the thing rather than a problem to solve.

Design rules

These are constraints the project holds itself to, not aspirations. They exist because you are going to run this on the machine you work on, and an experimental desktop should not be able to leave you without a computer on a Tuesday morning.

debs only

No install script, no post-install download, no manual file copying. If it cannot ship in a package, it does not ship.

GNOME stays

Installed, selectable, and supported. Gridline is additive and removable, and no change may replace or remove the Ubuntu session.

no edits to others' files

GDM, PAM, NetworkManager, PipeWire, and polkit are influenced only through named drop-ins under paths Gridline owns.

archive packages first

Preferred over third-party sources, so what is installed is what Ubuntu ships.

one compositor, one boundary

Hyprland sits behind an adapter in a single location, and a build gate fails the build if a compositor name escapes it.

How it works

Everything Gridline ships is a Debian package. When you pick Gridline at the login screen, a small launcher starts the compositor and then checks, against the running session, that every piece the desktop promises is actually there: locking, idle detection, output management, screen sharing.

If a piece is missing, the session says so. The launcher writes which piece failed to the system journal and returns you to the login screen, where your usual Ubuntu session is still one click away. Gridline would rather not start than start as a broken desktop you cannot explain.

Make it yours

The shipped defaults live under /etc/xdg/gridline/, and anything you write in ~/.config wins over them. That is verified behavior, not a promise: the session was measured preferring a user's own configuration over what the packages ship.

The shell is stock archive software: the bar is waybar, the notifications are mako, the wallpaper is hyprpaper. Every upstream document and every dotfile the community has written for them applies to Gridline unchanged. Configuration resolution, including where the compositor's own file is searched, is written down in configuration.md.

The support gap, stated plainly

Every piece of the compositor stack Gridline depends on (Hyprland, its portal backend, the Wayland tools) comes from Ubuntu's universe component. Canonical does not commit to security updates for universe; it does for main. So a Gridline install inherits no CVE-response commitment for its compositor, locker, or portal backend.

Patching those is your responsibility, the way it already is for anything tiling you would install by hand today. A Gridline-maintained PPA tracking upstream CVEs is recorded as a future goal, not a promise. This gap is a design fact of the project, recorded in its documentation, and this site does not hide it.

Status

Early development, in the open. Verified end to end in a VM, including the failure path:

  • GDM session entry, launcher, and capability gate
  • Hyprland adapter behind the compositor boundary
  • Status bar: workspaces, clock, and network, read off the screen and matched against the system's own view
  • Styled notifications; critical ones stay until dismissed
  • Wallpaper anchored to the release's own image
  • Application launcher on SUPER D, command menu on SUPER SHIFT D; the menu dispatches on entries, not typed text, so a free-typed word that matches nothing cannot fire a destructive action
  • Fail-safe screen lock: a locker that exits without an unlock is replaced, so a crashed locker never leaves the session unlocked
  • Session hygiene: shell components start only in a Gridline session, and the stock Ubuntu session was measured untouched
  • Portal integration
  • Full configuration defaults

Everything is planned as tracked changes, not vapor.

Follow along

The source repository holds the code, the OpenSpec change history, and the design documents. The design is written down before it is built, so the repository reads as a record of decisions, not just commits. The canonical development home is a self-hosted Forgejo mirror that receives the same history; GitHub is where the project is visible.
