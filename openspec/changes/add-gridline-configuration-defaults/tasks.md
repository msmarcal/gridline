# Tasks

## 1. The measurements the design rests on

These come first because the rest is built on their answers. A task here that returns an unexpected answer changes the design rather than being worked around.

- [ ] 1.1 Establish whether the compositor's `source` directive accepts an absolute path, by writing a configuration that sources a file under `/etc/xdg` and confirming a setting from the sourced file is in effect. Verify by asking the running compositor for that setting's value rather than by the session appearing to work, and record the command that answered
- [ ] 1.2 Establish what a running compositor can be asked that distinguishes Gridline's configuration from the autogenerated one. Verify by reading the candidate back on a session running each, and record both answers; if nothing distinguishes them, say so, because the third scenario of the new requirement depends on this
- [ ] 1.3 Confirm the documented search order against the binary on the baseline rather than against the document: with no user file, a file at `/etc/xdg/hypr/hyprland.conf` is read; with a user file present, it is not. Verify each half separately, and clean up both test files afterwards
- [ ] 1.4 Establish how the session sets `LockedHint`, by calling `SetLockedHint` on the session object and reading the property back. Record which session object path the call must target and how it is derived, since a session's object path is not fixed
- [ ] 1.5 Confirm `swayidle` is still the right selection against the archive, re-reading which libraries it links rather than citing the previous change, and record the events its manual documents for timeout, the logind lock signal and suspend

## 2. The defaults themselves

- [ ] 2.1 Author the compositor defaults under `src/adapters/<compositor>/`, covering tiling, workspaces, focus movement, window placement and the Super-centric keymap. Verify the file is inside the adapter path by running the isolation check, which must still report zero references outside it
- [ ] 2.2 Author the loader that sits at the compositor's search path and sources the defaults. Verify on the VM that a session started with no user configuration has the defaults in effect, using the answer from 1.2 rather than inference
- [ ] 2.3 Ship both through `gridline-config` rather than `gridline-session`, and verify with `dpkg -L` on the built package that the installed paths belong to the package `package-delivery` names, not the one whose source tree holds the file
- [ ] 2.4 Verify the two gates pass and account for the ownership gate's file count, which must rise by the number of files this change ships and by no more
- [ ] 2.5 Register the shipped defaults as conffiles and verify with `dpkg-query -W -f='${Conffiles}'` on the built package, since an administrator is expected to edit them

## 3. The isolation gate matches names as well as contents

- [ ] 3.1 Extend `tools/check-adapter-isolation` to match the reference list against file names as well as contents. Verify by planting a file named for a compositor outside the adapter path, with contents that match no reference, and confirming the build fails
- [ ] 3.2 Verify the extension does not break the existing check, by planting each of the eleven references as content outside the adapter path one at a time and confirming the build still fails for every one
- [ ] 3.3 Record in the check's own comments what it still cannot catch, since a compositor configuration under a neutral name passes both halves

## 4. Locking happens without being asked

- [ ] 4.1 Declare the idle daemon as a dependency of `gridline-session` and verify with `dpkg-deb -f` on the built package rather than by reading the control file
- [ ] 4.2 Author the lock entry point, setting `LockedHint` true before the locker starts and false after it exits. Verify the false path runs whatever the exit reason, by exercising a normal unlock and a killed locker and reading the property after each
- [ ] 4.3 Route the idle timeout, the suspend hook and the key binding through that one entry point, with the binding asking logind to lock rather than running the locker. Verify by reading the journal for a lock triggered each of the three ways and confirming the same entry point ran
- [ ] 4.4 Verify the session locks itself after the configured period, timing it rather than assuming, and that authentication is required to return
- [ ] 4.5 Verify `LockedHint` reads true while locked and false after unlocking, which is the debt `add-session-lifecycle-integration` recorded and could not close
- [ ] 4.6 Verify the hint is not left true when the locker fails to start, since a system that believes an unlocked session is locked is the failure this ordering exists to prevent

## 5. Recovery from a dead locker

- [ ] 5.1 Ship a default for `misc:allow_session_lock_restore` and verify the setting is in effect on a running session by reading it back from the compositor
- [ ] 5.2 Verify the measured lock-failure state is now recoverable from the machine itself: lock, kill the locker, and confirm a working lock screen can be restored and the session returned to, without another machine and without ending the session
- [ ] 5.3 Verify the session is still held locked throughout that recovery, since the scenario this serves is about not exposing the session and a recovery path that exposes it is worse than none

## 6. First login

- [ ] 6.1 Verify on the VM, from a user account with no configuration of its own, that launching a terminal, closing a window, moving focus and switching workspaces all work from the keyboard. Record which keys, since the scenario asks that the user not have to consult the compositor's documentation
- [ ] 6.2 Verify a user's own configuration does not silently discard the defaults: write one, confirm the defaults are gone, and confirm the condition is detectable by the answer from 1.2 rather than only by the user noticing a key that does nothing
- [ ] 6.3 Verify absent defaults degrade rather than block, by removing `gridline-config` and confirming the session still starts and reaches a desktop
- [ ] 6.4 Verify the stock GNOME session is unchanged by any of this, since every mechanism here writes into paths a Gridline session reads and the fallback must be untouched

## 7. Coherence

- [ ] 7.1 Verify each scenario of the two modified capabilities is either exercised or recorded as unexercised with a reason, naming the file or measurement for each, and that none is left unaccounted for
- [ ] 7.2 Update `docs/configuration.md`, `docs/component-ownership.md` and `docs/user-experience.md` for the selection, the resolution mechanism and the elements of the target experience now delivered. Verify by grep that no live document still describes the compositor configuration as unaddressed or the idle daemon as unselected
- [ ] 7.3 Verify the two rules this change reconciles are recorded as reconciled where a reader meets them, not only in this change's design, since the archived design is not where someone looks
